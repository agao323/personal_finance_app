# Frontend

Next.js App Router, TypeScript, Tailwind, `pnpm`, in `web/`. The web app is a
backend-for-frontend: it renders pages and proxies `/api/*` to a private API.

## This is not the Next.js you know

**Next.js 16.3.1.** It has breaking changes from what most training data describes —
`middleware.ts` is now `proxy.ts`, and APIs and file conventions differ. Before writing
Next code, read the relevant guide in `web/node_modules/next/dist/docs/` (installed with
the package, so it matches the version exactly) and heed deprecation notices.
`web/AGENTS.md` carries the same warning in a block that `next dev` regenerates — leave it
alone. Version-pinned notes: [references/nextjs-16-llms.txt](references/nextjs-16-llms.txt).

## Layers

```
lib/api-types.ts ──► lib/api.ts ──► components/ ──► app/ (routes)
```

| File | Rule | Enforced by |
|---|---|---|
| `src/app/api/[...path]/route.ts` | **The only code that knows the API URL** (`INTERNAL_API_URL`, server-side). Forwards everything under `/api/*` to the private API | `scripts/check_no_public_api_url.sh`; the ESLint `fetch` rule |
| `src/lib/api.ts` | **The only fetcher in the browser.** `apiFetch(path, { method, params, query, body })` takes a relative route string from the contract and infers the response type from it; an absolute URL throws | ESLint: `fetch()` anywhere else fails lint |
| `src/lib/api-types.ts` | **Generated by `make types`, never hand-edited.** Imported with `import type` only — it has no runtime exports | `make types-check` in CI; ESLint: a value import fails lint |
| `src/proxy.ts` | Next 16's middleware (not the proxy route, despite the name). Verifies the Cloudflare Access JWT before rendering and answers a failure with a human page, not a bare "Forbidden" | `proxy.test.ts` |
| `src/lib/access.ts` | Access JWT verification: signature, issuer, audience, via `jose`. Disabled when unconfigured, so dev and demo run without a team domain — and both `CF_ACCESS_TEAM_DOMAIN` and `CF_ACCESS_AUD` must be set, because either alone accepts tokens it should not | `proxy.test.ts`; [references/cloudflare-access-jwt-llms.txt](references/cloudflare-access-jwt-llms.txt) |

Why the browser never calls the API directly: [design-docs/request-path.md](design-docs/request-path.md).

### Using `apiFetch`

```ts
const ready = await apiFetch("/ready");                                   // typed response
await apiFetch("/accounts", { method: "post", body: { … } });             // typed body
await apiFetch("/accounts/{account_id}", { params: { account_id: 7 } });  // keep the literal
```

- Keep the route literal and pass `params`; interpolating the id and casting back throws
  away the inference the client exists for. A missing parameter throws rather than
  requesting `/accounts/%7Baccount_id%7D`.
- `formData` is the escape hatch for the one multipart route (CSV preview); content-type is
  left unset so the browser adds its boundary.
- Errors are `ApiError(status, detail)`, from the single `ErrorResponse` shape. A `401`
  fires `SESSION_EXPIRED_EVENT` rather than redirecting mid-fetch, which would discard
  whatever the reader was doing; the layout offers to sign in again.

## The contract, from this side

`api-types.ts` is generated from the API's Pydantic models
([design-docs/api-contract.md](design-docs/api-contract.md)). **Never hand-write a response
type.** Use `ResponseOf<"/path", "get">`, `BodyOf`, `QueryOf` from `lib/api.ts`, or
`components["schemas"][…]` from `api-types` with `import type`. If a shape is missing,
change the Pydantic model and run `make types` — never work around the contract in the
browser ([ADR 0006](adr/0006-contract-changes-during-wave-2.md) has four examples of why every
workaround was worse).

**Money is integer cents and percentages are basis points** everywhere in the browser.
Parse money by splitting the string (`lib/format.ts` `parseDollarsToCents`), never by
multiplying — `parseFloat("12.34") * 100` is `1233.9999999999998`. A half cent rounds away
from zero to match the server's `ROUND_HALF_UP`. Money inputs are `type="text"`: a number
input silently discards what it cannot parse.

**Never re-derive a rule the server owns.** Urgency (`is_urgent`), which period a date is
in, a perk's reset schedule, group subtotals, ownership-adjusted values — the browser reads
them off the API. A second implementation in TypeScript would disagree eventually, and the
disagreement would look like a credit you were told you still had.

## Tests

- **vitest + Testing Library + MSW.** Component and page tests run against MSW handlers in
  `src/test/msw.ts`, whose fixtures are typed with `ResponseOf<…>`: a mock cannot describe a
  response the API will never send, and a model change without `make types` stops them
  compiling.
- What mocks cannot catch is *semantic* mismatch — `[]` where a component assumed `null`,
  a sparser series than a chart expected. That is what the two Playwright smoke tests in
  `web/e2e/` are for (dashboard against the seed; the CSV wizard end to end), run by
  `make e2e` against the deploy-shaped stack.
- Colocated: `foo.tsx` beside `foo.test.tsx`. `vitest.setup.ts` restores Node's `File` and
  `Blob`, because MSW's multipart parser rejects jsdom's.
- The lint rules themselves are tested: `web/src/lint-rules.test.ts` lints violating
  snippets and asserts each rule fires.

## Component ownership and conventions

Components live in `src/components/`, grouped by feature (`cards/`, `charts/`, `forms/`,
`import/`, `rules/`, `tiles/`). Routes in `src/app/(dashboard)/` compose them. Parallel
plans have owned one component file each (Wave 7's 055–059), which is why shared
components take their data as props and stay free of page state:

- `transaction-table.tsx` is shared by spending, account detail and transactions. Selection
  and inline editing are **optional props**, so read-only callers carry no mode flag.
- `states.tsx` holds `Skeleton`, `Refreshing`, `ErrorState`, `EmptyState`, `StaleBadge` —
  loading and error states, never spinners over blank space. Empty states carry the next
  action.
- `forms/fields.tsx` gives every field `aria-describedby` and `aria-invalid` once.

Patterns the tickets settled, each after getting it wrong once:

- **Optimistic updates roll back per row**, not by snapshotting the list — two writes can be
  in flight (030). Failures revert visibly.
- **One refresh signal per screen**: a change anywhere refetches everything that could have
  changed (061), and refreshes update in place rather than flashing skeletons (070).
- **Controls sit with their subject** — a card's rename, delete and fee controls are on
  the card's own panel, not in the list (072).
- **Never colour alone.** Urgency and staleness carry a glyph or word too; colour is the
  amplifier. Icon-only buttons carry an `aria-label` and a visible tooltip (064). A row
  control's accessible name includes something that distinguishes it, like the date (030).
- **`localStorage` is wrapped in try/catch** — it throws outright in some contexts (056).
- Design tokens are CSS variables with light and dark values; status text uses the
  `--*-text` steps, because raw status hues fail contrast as text (064).
- The demo build (`NEXT_PUBLIC_DEMO=true`, a build arg) contains no sign-in path at all and
  shows a permanent synthetic-data banner ([product-specs/demo.md](product-specs/demo.md)).
