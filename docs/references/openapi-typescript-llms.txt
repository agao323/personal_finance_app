openapi-typescript — how the contract becomes TypeScript
========================================================

Pinned version: openapi-typescript 7.13.0 (web/package.json devDependency)
Source: web/node_modules/openapi-typescript/README.md (the installed package)
        Upstream docs: https://openapi-ts.dev
Verified: 2026-09-27, against the installed 7.13.0 README and this repo's generated output

WHAT IT DOES
Reads an OpenAPI 3.0/3.1 document (JSON or YAML, local or remote) and emits a runtime-free
.ts file of types. No code generation of clients, no Java, no running server.

HOW THIS REPO RUNS IT (`make types`)
1. cd api && uv run python scripts/export_openapi.py  -> api/openapi.json (gitignored)
   (builds app.openapi() from the Pydantic models; needs no database)
2. cd web && pnpm exec openapi-typescript ../api/openapi.json -o src/lib/api-types.ts
3. prettier --write on the output, ignoring .prettierignore (which otherwise skips it)
`make types-check` runs the same and fails if web/src/lib/api-types.ts changed.
The file starts "This file was auto-generated by openapi-typescript. Do not make direct
changes." Never hand-edit it; change the Pydantic model and regenerate.

SHAPE OF THE OUTPUT (what code imports)
- `paths`: keyed by route string, then method. Unimplemented verbs are emitted as
  `put?: never` rather than omitted — so "does this path support GET" must be tested by the
  operation having `responses`, not by key presence. web/src/lib/api.ts (`PathsWith<M>`)
  does exactly that.
- `components["schemas"]["Name"]`: the Pydantic models. Import with `import type`.
- `operations["operation_id"]`: per-operation parameters, requestBody, responses.
- Router and schema docstrings become JSDoc @description comments in the output. So editing
  a docstring on a route or a response model changes api-types.ts — and trips types-check.
  Several of those docstrings cite docs/ARCHITECTURE.md anchors, which is why those anchors
  must not be renamed.
- Multipart request bodies are emitted as an object of field names, not something
  JSON.stringify produces; api.ts has a `formData` escape hatch for the one such route.
- Pydantic fields with default_factory are emitted as optional; a response field the API
  always sends should be required in the model (see schemas/net_worth.py).

HOW IT IS CONSUMED
web/src/lib/api.ts derives request and response types from `paths` (ResponseOf, BodyOf,
QueryOf) so a route string typo or a wrong response assumption is a compile error.
web/src/test/msw.ts types fixtures with ResponseOf<...>, so mocks cannot drift from the API.
The ESLint rule in web/eslint.config.mjs rejects value imports of api-types.

RECOMMENDED TSCONFIG (from the README) — this repo's web/tsconfig.json uses bundler module
resolution, which the README lists as supported.
