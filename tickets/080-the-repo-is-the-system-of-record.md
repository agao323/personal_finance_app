## Goal
Any future agent can start from one short map, reach every doc in at most two hops, and
trust what it reads because mechanical checks keep the docs true. Structure and
enforcement only — **no feature or behaviour change**. If `make types` produces a diff,
this ticket went out of scope.

The pattern is OpenAI's "harness engineering": a short root map, a `docs/` tree with
progressive disclosure, plans as versioned artifacts, and checks that fail when a doc
drifts from the code.

## Rules for every sub-ticket
- Never open anything under `data/`. Describe data by structure, never by values. The
  new checks skip `data/` entirely.
- `make lint && make test && make types-check` green at every commit.
- ADRs and `DECISIONS.md` are history: never renumber or rewrite a decision. Fix links;
  add a "superseded by" banner only where it is true.
- Moving prose is fine; dropping a "why" is not. Every section of today's docs is in the
  move map below or listed as intentionally dropped.
- Filenames that already fit stay: `ARCHITECTURE.md`, `PRODUCT.md`, `SECURITY.md`,
  `DECISIONS.md`, `adr/`, `runbooks/`, and every ticket filename.
- `web/AGENTS.md`'s nextjs-agent-rules block is regenerated by `next dev`. Leave it.

## Decision: the endpoint table moves, it is not generated

`test_contract.py` parses a hand table and guarantees two things: the documented routes
equal the app's, and every row names the ticket that landed it. Two ways to keep that:

1. Generate the table and carry the ticket as route metadata (`openapi_extra`).
2. Move the hand table to `design-docs/api-contract.md#endpoints` and repoint the test.

**Option 2.** Route metadata means editing about forty route decorators across twelve
router files and changing `openapi.json`, so this ticket's no-diff rule for `api-types.ts`
would depend on how `openapi-typescript` treats `x-` extensions — a behaviour change risked
for a documentation move. And the ticket column is build history, not a property of the
running API; serving it from `/openapi.json` puts provenance in the runtime contract. The
generated `api-endpoints.md` covers everything that should never be hand-kept (methods,
parameters, request and response models); the hand table keeps the one column only a
person can supply, and the test still fails if it drifts.
